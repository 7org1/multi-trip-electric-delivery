# 第五个算法：RL-GBKA 设计说明

## 一、为什么不直接"用 GBKA"

GBKA 的四个核心算子在置换空间上没有定义或代价过高：

| 原始算子 | 置换空间的问题 |
|---|---|
| 灰狼三父代 `(X1+X2+X3)/3` | 三个排列的平均 = Kemeny 问题，NP-hard |
| 黄金正弦 `X·|sin(r)|` | 排列乘标量无定义 |
| 反向学习 `2c - X` | 需要"中心"，即 Kemeny 均值，NP-hard |
| 随机键 + `sort()` | 可用，但映射分段常数，产生大量"空转" |

**结论：保留 GBKA 的策略层，替换算术层。**

## 二、组件映射

| GBKA 原始组件 | 本设计的对应物 | 保留了什么 |
|---|---|---|
| 灰狼三父代（向精英靠拢） | **O8 精英引导重组** | "多父代向精英收敛"的思想 |
| 黄金正弦（局部精化） | **O2 相关移除 + regret 修复** | "在精英附近小幅扰动"的思想 |
| 反向学习（多样性） | **O1 远端移除**（移除离当前解最远的客户） | "反向"= 跳出当前区域 |
| 自适应权重调度 | **RL 策略网络** | 调度机制从手工规则升级为学习 |
| 精英存档 | **精英存档**（原样保留） | 跨迭代记忆 |
| 停滞重启 | **O4 路径消除 + O3 大幅破坏** | 跳出局部最优 |

**算术层被整个丢弃，策略层全部保留 —— 这是可以写进论文的迁移逻辑。**

## 三、算子库（8 个离散算子）

| 编号 | 算子 | 类型 | 作用 |
|---|---|---|---|
| O1 | 远端移除（far removal） | 破坏 | 多样性，相当于离散化的"反向" |
| O2 | 相关移除（Shaw removal） | 破坏 | 局部精化 |
| O3 | 大比例随机移除 | 破坏 | 跳出局部最优 |
| O4 | **路径消除尝试** | 破坏 | **降车辆数**，四个基线都没有 |
| O5 | 最差移除（worst removal） | 破坏 | 剔除劣质客户 |
| O6 | 最优插入（greedy repair） | 修复 | 标准修复 |
| O7 | 后悔值插入（regret-2 repair） | 修复 | 更强的修复 |
| O8 | 精英引导重组 | 重组 | GBKA 三父代思想的离散版 |

**破坏算子和修复算子成对使用（O1–O5 × O6/O7），O8 单独使用。**

**O4 是差异化关键**：前四个基线都因缺少路径消除而卡在 21 车，如果 O4 有效，RL-GBKA 能到 20 车 —— 这是一个可测量的、结构性的优势。

## 四、RL 调度器

### 状态（24 维）

```
[1]     当前解罚函数值（归一化）
[2]     历史最优值（归一化）
[3]     停滞代数 / 窗口
[4]     当前解的车辆数 / m
[5]     当前解容量违反量（归一化）
[6]     当前解时间窗违反量（归一化）
[7]     精英存档当前最好距离（归一化）
[8]     精英存档多样性（平均成对距离）
[9-16]  8 个算子的近期成功率
[17-24] 8 个算子的近期使用次数（归一化）
```

### 动作（8 选 1）

8 个算子之一。

### 策略网络

```
输入 24 → 全连接 64 (ReLU) → 全连接 64 (ReLU) → 输出 8 (softmax)
参数量：24*64 + 64 + 64*64 + 64 + 64*8 + 8 = 6,344
```

**CPU 单次前向约 6 μs，可每 20 次迭代决策一次，开销可忽略。**

### 训练

REINFORCE + 基线（移动平均），CPU 可训练。
不用 PPO 是因为 MATLAB 手写 PPO 的 clip/GAE 容易出错，而 REINFORCE 在小动作空间上足够。

## 五、与问题的耦合（关键）

求解器**不直接访问 S**，只通过 `problem` 结构体：

```matlab
P.n, P.N, P.m, P.Q, P.depot
P.demand, P.ready, P.due, P.service
P.eval(routes, lam)            -> [f, viol, R]
P.insert(routes, j, allowNew)  -> [r, p, delta, found, perRoute]
P.stats(route)                 -> st.dist, st.capExcess, st.twExcess
```

**两个实现：**

| 场景 | 适配器 | 说明 |
|---|---|---|
| Solomon / G&H（静态） | `problem_static.m` | 距离 = 时间，直接查表 |
| 南京真实路网（时变） | `problem_td.m`（待建） | `P.stats` 内部调用 TD 最短路 |

**求解器代码一行不用改** —— 这是"适用于未搭建的建模场景"的实现方式。

**时变版本需要补的只有一个函数**：`problem_td.m` 里的 `routeStats`，它要在给定出发时刻时，为每段选时变最短路径。其余接口签名不变。
